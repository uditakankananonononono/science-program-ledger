## Headline question
A zero-hit result on 13-16-mers is expected for any short cationic peptide under default settings. "32/32 novel" is informative only if the same pipeline flags known sequences as NOT NOVEL. The sensitivity gate G is the core criterion. G failing in N1 is a legitimate, expected outcome.

## Hit rule (identical in every arm)
A hit is any single HSP (all arms) meeting both thresholds; HSPs from one subject are not merged. Identity = identities / alignment length. Coverage = aligned query residues / query length. HSP with coverage >= 80% and identity >= 90%: candidate is NOT NOVEL. HSP with coverage >= 80% and identity in [70%, 90%): NEAR. Else NOVEL. Sub-80%-coverage hits are listed, ignored by the rule. For L1 and L2, identity is computed from the alignment strings (identities / alignment length, from qaln/taln), NOT from the mmseqs pident field; coverage = (qend - qstart + 1) / qlen. mmseqs yields one alignment per query-target pair, so non-merging of HSPs is automatic there. The driver prints mmseqs default --min-seq-id and gap open/extend values to guard against version-default drift. If a hitlist length equals the cap (100), the query is flagged "at cap" and reported.
## Control sets (driver committed and hash-pinned before any query; dry-run on synthetic data only)
Two independent draws: draw 1 seed 200200, draw 2 seed 200201. Both are run and reported.
Source: Swiss-Prot entries with creation date <= 2026-09-01. Windows containing X/B/Z/U/O are excluded. Signal-peptide rule: windows overlapping an annotated signal peptide (SIGNAL feature) are NOT excluded (candidates are unannotated, so a plain-window rule is used); the SIGNAL overlap is recorded per control.
Matching, per candidate: exact length; Shannon entropy within +-0.15 bits; hydrophobic fraction (AVILMFWC) within +-0.15; K+R fraction within +-0.10. A window matching a candidate by any shared 6-mer is excluded. If no window satisfies all constraints after 10000 draws, the control is recorded "unmatched" and counts as NOT flagged (adverse to the gate).
C1: exact Swiss-Prot window per candidate (32). Expected NOT NOVEL.
C2: each C1 window with exactly one substitution: position uniform over all positions including termini, replacement uniform over the other 19 residues. Identity and coverage recorded per control. Expected NOT NOVEL (identity 92.3-93.8%).
C3: two substitutions, report only, run in L1 and L2 only; NOT submitted to N1 (N1 total 32 + 2x96 = 224 singles excludes C3).
C4: each candidate residue-shuffled with the draw seed, negatives, expected NOVEL.
## Criteria (fixed now)
G per arm: PASS iff, in BOTH draws separately, C1 >= 30/32 flagged NOT NOVEL AND C2 >= 28/32 flagged NOT NOVEL (no pooling). Clopper-Pearson 95% lower bounds reported for C1 and C2 per arm per draw.
S specificity: C4 flagged NOVEL >= 0.95 per draw; any C4 miss is explained individually (accession, identity, coverage). Arm is "discriminating" iff G passes and S passes.
A: number of the 32 candidates with NO NOT-NOVEL hit, per arm, with per-candidate evidence. NEAR is reported separately ("still novel under the claim's rule; near hit exists") and does not reduce A. Only NOT NOVEL flips trigger the "not reproduced" label. Same definition for S: a C4 miss is a NOT NOVEL call only; C4 NEAR calls are reported and explained but are not misses.
Combined novelty-vs-nr statement requires N1 AND L1 both G-pass. L1 alone covers Swiss-Prot only and does not carry any statement about nr. N2 and L2 are reported with the same gate, not part of the combined label.
## Outcome labels (fixed; "novelty is not activity" appended to every label)
- N1 and L1 both G pass, S pass, A = 32/32 in both: "32/32 novel reproduced against current nr and Swiss-Prot; sensitivity shown on Swiss-Prot-derived known sequences only; not shown for unannotated or patent-only sequences in nr."
- G pass in one of N1/L1 and A=32/32 in that arm only: "novelty reproduced for arm X only; sensitivity shown on Swiss-Prot-derived known sequences only; no claim for the other database."
- G pass, N1 and L1 disagree on any candidate: "G pass, N1 and L1 disagree: k candidates NOVEL in one arm and not the other", listed per candidate.
- G fail with point sensitivity >= 0.80 in both classes (C1 and C2) in both draws: "inconclusive (near threshold) for arm X"; no 32/32 novelty claim is made.
- G fail with point sensitivity < 0.80 in any class or draw: "32/32 novel result uninformative for arm X (pipeline did not detect known sequences)". Applies even if A = 32/32. This is a legitimate expected outcome for N1.
- A NOT NOVEL flip in any G-pass arm: "32/32 novel not reproduced: k candidates now have hits (drift d, pre-existing e, undetermined u)".
- Any arm or item that cannot run: "not run", never counted as pass.
## nr growth since 2026-09-27: drift vs error (fixed)
For each flipped candidate (NOVEL to NEAR/NOT NOVEL): date the hit. NCBI: EARLIEST create date over all identical-sequence members (NCBI identical-proteins list); efetch dates are record dates, not proof of first public availability. UniProt: later of entry creation and last sequence-update. Hit date > 2026-09-27: "drift". Hit date <= 2026-09-27: "hit exists with date <= 2026-09-27; original result did not report it; cause (pipeline difference vs defect) undetermined". No date retrievable: "undetermined".

## Courtesy, retry, throttle (sources read 2026-10-10)
Sources: https://blast.ncbi.nlm.nih.gov/doc/blast-help/developerinfo.html states: do not contact the server more often than once every 10 seconds; do not poll any single RID more often than once a minute; run scripts weekends or between 9 pm and 5 am Eastern on weekdays if more than 50 searches will be submitted; users submitting more than 100 searches in 24 hours may be moved to a slower queue or, in extreme cases, blocked; large projects should use stand-alone BLAST or a cloud provider. https://www.ncbi.nlm.nih.gov/home/about/policies/ repeats the weekend/9pm-5am rule for scripted series. Today (2026-10-10) is a Saturday; the weekend rule is satisfied for submissions made on Saturday/Sunday. Weekday continuation runs only between 9 pm and 5 am US Eastern; the driver never submits outside the window, and any item not submitted by the end of the program is "not run", never retried outside the window. Actual submission hours (UTC and US Eastern) are recorded per RID.
Every request carries tool=algo50-r05-audit and email=sspou3@mail.instinct.com (the agent mailbox; no personal address of the user is sent). This prereg SUPERSEDES the draft's 30 s polling: poll each RID no more than once per 60 s, submissions >= 10 s apart (driver uses 15 s), at most 3 RIDs in flight.
24-hour volume: NCBI's developerinfo page (re-fetched 2026-10-10) says: "We will move searches of users who submit more than 100 searches in a 24 hour period to a slower queue, or, in extreme cases, will block the requests." N1 is 224 single submissions. The driver caps submissions at 90 per rolling 24 h, a self-imposed margin under that line (not an NCBI number). Fixed order: candidates (32), draw-1 C1, C2, C4, then draw-2 C1, C2, C4. N2 (batched, ~5 RIDs) counts toward the cap. The draw-1 gate is therefore evaluable first; the full N1 run spans about three days. The order and cap are frozen before the first query. Account-less public API, no key. Hourly check note: nothing is re-polled faster than stated.
Early stop: after the 32 candidates and all draw-1 controls finish in N1, if C1 or C2 point sensitivity is < 0.80, N1 draw 2 is marked "not run (G already failed)". L1 and L2 still run for both draws.
Stop-on-throttle: any HTTP 429/503 that persists over 3 consecutive attempts, or any NCBI message about rate limits or a slower queue, stops N1 immediately; remaining items are "not run" and the situation is reported.
Per-RID timeout 60 min; up to 2 resubmissions on transient failure with the same query; then "not run" for that item. No parameter change after seeing any result.

## Scoring details fixed now
N2 is run on draw 1 only; its G is evaluated on draw 1 only and it is report-only. Early-stop and score use one denominator: all controls in the manifest (32 per class per draw), with unmatched or not-run controls counted as not flagged. ## Transient errors
HTTP 429/500/502/503/504 and network errors are retried with 60 s x n backoff; 3 consecutive failures stop the run (Throttle stop) for manual restart; the state file is resumable and the resumed run changes nothing. Per-RID failures follow the 2-resubmission rule.

## Throughput
