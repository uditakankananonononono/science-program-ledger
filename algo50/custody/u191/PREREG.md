# Unit 191 preregistration: concurrent heart-failure coding in a selected diabetes encounter

Status: pre-outcome design lock. This is a claims-style diagnosis-code classification experiment on an extract, not a clinical or prognostic model. Target is concurrent presence of ICD-9-CM code `428` in any of `diag_1`, `diag_2`, or `diag_3` of one deterministically selected encounter per `patient_nbr`. The target is coding on that encounter only; no subsequent heart-failure event, prognosis, clinical diagnosis, or treatment benefit is inferred.

## Features and leakage controls

Remove `diag_1`, `diag_2`, `diag_3`, `number_diagnoses`, and all ID fields (`encounter_id`, `patient_nbr`) from all models. `readmitted` is not a feature. Exclude weight due to extreme missingness and unreliable availability, and exclude `discharge_disposition_id` because it can encode end-of-stay outcome/status; missingness for these removed columns is not a feature. Include remaining source fields only as same-encounter concurrent descriptors; they are not represented as pre-admission covariates.

Remove HF drug-risk proxy features from the primary model: `pioglitazone`, `rosiglitazone`, `metformin-rosiglitazone`, `metformin-pioglitazone`, `glimepiride-pioglitazone`. These are drug exposure/change-status fields, not HF treatment fields. DailyMed prescribing information for pioglitazone (ACTOS; https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=b73e5856-e6f5-4239-80d9-fda136c4748b) states thiazolidinediones including pioglitazone can cause or exacerbate CHF; the rosiglitazone (AVANDIA; https://dailymed.nlm.nih.gov/dailymed/lookup.cfm?setid=ef14122b-7fff-45fa-b13b-0ea9e48bd57d) label says the same. Combo fields are excluded because they name one of these two drugs. This is a prespecified proxy list, chosen without outcome-driven iteration. Primary retains the other 18 anti-diabetic medication fields. A sensitivity removes all 23 medication columns together; report both. No effect is interpreted as medication causing HF.

Retained fields are demographics (age group, sex/gender, race), admission-source/type descriptors, length of stay and same-encounter utilization/lab/procedure/medication descriptors (excluding diagnosis and drug-proxy fields), laboratory result category fields, and allowed anti-diabetic medication status fields. Each is treated as concurrent information; no field is claimed to be available at admission. Categorical missing values are explicitly encoded as a missing/unknown state for sparse additive model; numeric missing values are median-imputed using DEV only and accompanied by an availability indicator. LightGBM uses explicit missing category/NaN handling as implemented; no TEST-fitted preprocessing. Age and time_in_hospital each receive four fixed cubic-spline basis columns in the sparse additive model; categorical retained fields are one-hot encoded. Coding/transforms are identical on a given input matrix for the comparable models where applicable.

## Pre-registered models and endpoint

Three fixed model classes, no hyperparameter search:

1. **Primary method candidate: sparse additive logistic model.** L1-penalized logistic regression, `C=0.1`; cubic spline basis with exactly 4 basis columns each for `age` group and `time_in_hospital`; one-hot encoding for retained categoricals with explicit missingness/availability states; DEV-only numeric median imputation with missingness indicators. This is a constrained additive representation with transparent per-feature effects, distinct from tree interactions in GBM. `C` and basis degrees are fixed before scoring; no feature selection.
2. **Strongest cost-matched tabular comparator: LightGBM.** Fixed 31 leaves, 100 trees, learning rate 0.05, seed 42; identical retained non-diagnosis feature set and leak exclusions, train-only fold preprocessing, no hyperparameter search. No diagnosis or label-derived features.
3. **Demographic baseline: logistic regression on age, sex/gender, race only**, with the same DEV-only encoding/missingness treatment and fixed L2 `C=1.0`.

Primary metric: ROC AUC for per-encounter code classification on held-out patients. During the one DEV headroom run, choose the comparator with greater DEV OOF AUC; if absolute AUC difference is <=0.001, choose LightGBM. Lock comparator identity in this prereg before TEST outcomes. Final paired improvement is candidate ROC AUC minus that DEV-locked comparator only; no TEST AUC is used to select it. WIN threshold is absolute +0.03. Report comparator values and candidate separately. Score test people once each, no repeated encounters. Secondary: PR AUC, sensitivity/specificity at threshold 0.5 (not tuned), calibration/Brier score, and age-bin-change/medication-sensitivity results. Confidence intervals and model deltas must resample patient IDs as clusters; no row/encounter bootstrap. Report per-patient deltas only as a cluster summary where defined, not as independent observations.

## DEV headroom, permutation, and gate

DEV-only evaluation uses deterministic patient-grouped five-fold out-of-fold predictions, folds assigned from DEV patient hash order round-robin; held-out patient appears in no training fold for that prediction. Main comparison is paired on the same held-out DEV patients. Before lock, exactly one DEV headroom run and one DEV label-shuffle smoke run are allowed. Record both in this prereg, including the DEV OOF AUCs and the comparator selected by the fixed 0.001 tie rule, then hash-lock. These are the only two pre-lock outcome computations; both prespecified sensitivities run only in final authorized evaluation, not pre-lock. The smoke uses one global permutation of DEV labels and evaluates every fixed grid member (three models) under the same pipeline; it is a leakage diagnostic, not an inferential permutation test. Report exact values; do not silently re-band or tune. After lock, no DEV or TEST target access until the final authorized evaluation runner. TEST permutation diagnostic and both sensitivity analyses are only included in that final runner, disclosed as outcome diagnostics, and are not accessed pre-lock.

Counts-based design planning before outcomes: selected cohort has 71,514 people; TEST 17,878, DEV 53,636. The scout supplied an approximate 25%-TEST MDE of 0.02608 at AUC 0.60 from a 1:3 matched design capacity of 10,417 positives / 31,251 negatives; its assumptions are unknown and it is contextual only. Recomputed planning approximation on the frozen split uses the Hanley-McNeil binormal single-AUC variance formula at AUC=0.60: `Q1=A/(2-A)`, `Q2=2A^2/(1+A)`, `Var(A)=[A(1-A)+(n1-1)(Q1-A^2)+(n0-1)(Q2-A^2)]/(n1*n0)`. Inputs: `n_test=17,878`, post-exclusion prevalence `10,786/71,514=0.150823615`, giving expected `n1=2,696.425`, `n0=15,181.575`, `SE(A)=0.006156`. For paired AUC difference, assume zero covariance between the two model AUC estimators (independent; conservative relative to positive correlation), so `SE_diff=sqrt(2)*SE(A)=0.008706`; `MDE=(z_.975+z_.80)*SE_diff=(1.959964+0.841621)*0.008706=0.02439`. This is below the +0.03 threshold under this approximation; this is a planning bound, not a patient-cluster power guarantee. Final paired inference uses patient-level bootstrap, not this approximation. This is only an AUC sampling approximation; the final paired patient-level bootstrap accounts for the actual patient-level evaluation structure. DEV headroom gate: drop if the best comparator has AUC >=0.94 (within 2x the +0.03 win threshold of the AUC ceiling 1.0), or if it shows no skill above chance. The +0.03 threshold remains fixed; no success re-banding. Primary-diagnosis-only `diag_1 == 428` (3,980 full-cohort positives, already counted pre-split) is descriptive only and must not replace the primary endpoint.

### One-time staged DEV window execution plan (execution-only)
The single authorized pre-lock window is executed in the following fixed stage order, each stage once, with atomic create-once output files; existing stage output blocks rerun. The terminated attempt emitted only a candidate-model convergence warning and produced no complete result file; all partial process state is discarded. Stage order: candidate OOF folds 0-4; LightGBM OOF folds 0-4; demographic OOF folds 0-4; headroom/comparator/drop-gate aggregation; then candidate permutation-smoke folds 0-4; LightGBM permutation-smoke folds 0-4; demographic permutation-smoke folds 0-4. Each fold uses its fixed DEV hash-assigned validation fold and the globally permuted DEV labels seeded with 42 for the permutation stage. No intermediate result is inspected for model selection; the only branch is whether the fixed headroom DROP gate fires, in which case the permutation stages are omitted and the prereg records the stop. All recorded convergence warnings are retained in stage JSON; do not change iterations, tolerance, or model settings in response. Any need to alter these settings requires a new prereg lock before outcome access.
