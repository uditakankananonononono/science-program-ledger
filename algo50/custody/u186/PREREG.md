## Split and analysis

Split patients deterministically by SHA-256 of the literal BIDS subject ID (`sub-XX`), ascending digest bytes then subject ID as tie-breaker: the first 5 of 25 are sealed TEST and the remaining 20 are DEV. The split is not stratified or rerolled. Frozen TEST IDs are `sub-09`, `sub-12`, `sub-02`, `sub-19`, `sub-04`; all other 20 are DEV. The fixed SHA-256 subject-hash ordering is documented in `run.py`; the resulting ID list is included above. All model/feature/parameter decisions are made before TEST scoring. DEV model selection/headroom uses patient-held-out folds within the 20 DEV patients; each held-out patient is scored only by a model trained on other DEV patients. The five DEV folds use deterministic `GroupKFold(n_splits=5)` over sorted subject IDs, so no patient contributes to both training and held-out data. TEST outcomes are not computed in this task. If later authorized, PREREG and `run.py` hashes must be recorded before a TEST metric is computed, and TEST patients remain intact.

## Endpoint and hypothesis

**Single primary endpoint:** event-level average precision (area under the precision-recall curve) under the strict patient-independent protocol, for candidate minus authors-pipeline comparator. **Win bar:** absolute AP improvement of at least +0.03. The comparator is the authors' `final_pipeline` implementation reproduced under this same strict patient split, fixed gold-event/join policy, negative set, and score-based event metric, not the paper's leaky headline. Secondary: event sensitivity at a predeclared target precision of 0.80. Each model’s threshold is chosen on its own DEV out-of-fold scores to achieve 0.80 precision, counting score ties together; among feasible unique thresholds choose the one maximizing true-positive count, with lower threshold as tie-break. If a model cannot reach 0.80 precision at any threshold on DEV OOF, report this secondary endpoint as not achievable for that model, with no relaxed precision. Also report score-based ROC AUC and per-center event sensitivity at the same model-specific threshold. This is methodological benchmarking, not a clinical claim.

## Models and features

**Comparator:** faithful implementation of the authors' final_pipeline 14 selected predictors and LightGBM learner. Feature selection is exactly their hard-coded list: `teager_kaiser_energy_1_std`, `teager_kaiser_energy_2_std`, `chan_ptp`, `ptp_amp`, `hjorth_mobility`, `hjorth_complexity`, `teager_kaiser_energy_3_std`, `chan_kurt`, `teager_kaiser_energy_5_mean`, `teager_kaiser_energy_0_std`, `kurtosis`, `teager_kaiser_energy_1_mean`, `teager_kaiser_energy_5_std`, `samp_entropy`. Original notebook applies global undersampling before epoch-level CV and computes AUC on hard labels; the published 5-fold headline (precision 94.4%, sensitivity 94.3%, F1 94.3%, ROC AUC 94.3%, PR AUC 91.8%) is leaky contextual information and not the target. Its LOO values (precision 91.2%, sensitivity 86.7%, F1 87.5%, PR AUC 85.1%) also follow global undersampling and are likewise contextual only. Here the comparator's feature extraction and selected columns follow authors' code, but training-only undersampling and strict subject-held-out evaluation prevent leakage; AP and ROC AUC use scores.

**Candidate:** same 14-feature budget, same LightGBM learner, same subject folds and event scoring. Replace the within-epoch handcrafted feature block with six fixed Haar wavelet energy features (five detail levels plus final approximation; 6 scalar features total) and signed lag autocorrelations at fixed lags `{1,2,4,8,16,32}` samples (6 scalar features), retaining the authors' two channel-context covariates `chan_ptp` and `chan_kurt`. Epoch samples are per-epoch z-scored before the parameter-free morphology transform. No feature selection, thresholds, or hyperparameters are selected using outcomes. The implementation uses PyWavelets Haar DWT with symmetric extension at level 5; coefficient energies are mean squared values for `[A5,D5,D4,D3,D2,D1]`. Each 250-sample epoch is centered and divided by its standard deviation; constant epochs map to zero. Signed lag autocorrelation is `dot(x[:-lag],x[lag:])/dot(x,x)` after this normalization, or zero for constant epochs. Fixed learner seed is 42. If candidate gain is <0.01 AP, repeat paired candidate-vs-comparator comparison with seeds 17 and 29 as a sensitivity check, without tuning or replacing primary seed-42 result.

## Confounds and limitations

Tel Aviv Sourasky (9 patients; 50 Hz line frequency) and UCLA (16 patients; 60 Hz) are perfectly separated by line frequency. This is a serious center/line-frequency confound; leave-center-out analysis is sensitivity only, not independent site validation. Sub-09's event-count/mapping discrepancy and the onset deltas above are named label-integrity limitations. The archive has 980 SEEG rows versus the paper's stated 857; candidate/comparator channel-universe distinction is explicit. Patient counts, unequal channel counts, and unequal durations make epochs non-independent; patients, not epochs, define split units. No claim of clinical efficacy, generalization to unseen centers, or diagnostic utility will be made.

## Power / precision note

Only 25 patient clusters exist (20 DEV/5 held TEST under this deterministic split). A patient-aware estimate has low effective sample size despite thousands of windows: report per-patient event AP/sensitivity and the distribution across held-out patients; any uncertainty interval or comparison must resample patients as clusters, not epochs. This is a headroom screen, not a confirmatory powered clinical study. Between-center confounding and annotation differences further limit precision and transportability.
